## 1. 对《音乐情感表达指南》的审计结论

### 1.1 可直接内化的硬约束

1. 情绪是时间中的多维变化，不是标签；系统使用 valence / arousal / tension / distance 四条随时间变化的曲线。
2. 大调/小调、快/慢不能单独决定情绪；本工程在生成时同时改变和声、音域、密度、发音、音色、空间，并且不提供“快乐大调”按钮。
3. 细腻来自相关变化；Humanizer 以乐句为单位生成连续漂移、力度拱形、句尾收束，不做逐音独立随机。
4. 重复负责记忆，变奏负责发展；动机被保存并追踪，变奏记录在 `motifUses` 中。
5. 对比与克制优先；三套示范都在高点前后安排减法、停顿或撤层。
6. 去掉复杂音色仍应成立；示范工程的全部信息首先存在于 MIDI 音符、和弦、力度和曲线中。
7. 力度联动起音、亮度、噪声与释放；Felt Piano 的力度会同时改变模态倾斜、锤击噪声和包络。
8. 微时序服从乐句和声部；Humanizer 的偏移由乐句位置、声部角色和节拍位置决定。
9. 空间用于心理距离；每个音都有 reverb send，效果链不是把整体泡在长混响里。
10. 可编辑、可局部重生成、可撤销、可 A/B、可复现；这些在核心和 UI/CLI 中都有真实实现或明确标记。

### 1.2 指南中的模糊点与本工程的工程化解释

| 指南表述 | 工程解释 | 证据标签 |
|---|---|---|
| “效价影响和声稳定度、音区、音色、解决方式” | 映射为 `brightness`、`harmonicTension`、终止解决倾向；不直接切换大小调 | H |
| “唤醒度影响速度、密度、节奏清晰度” | 映射为密度、发音、力度范围；速度由风格参数给定，不按标签自动跳变 | H/C |
| “距离感影响干声比例、早期反射、宽度” | 映射为每轨/每音 reverb send、高频阻尼、立体声宽度 | H/R（空间线索的部分证据） |
| “克制—外放” | 作为 `Restraint` 乘数，降低或扩大力度范围与密度 | H |
| “文化背景” | 只作为显式输入与文档声明，不声称系统已掌握所有文化规则 | C/? |

## 2. 对《自然感音色生成提示词》的审计结论

### 2.1 已落实的硬约束

1. **激励 → 共振 → 辐射/传播**：Felt Piano 由锤击噪声、模态弦列、琴体共振和空间送出组成；Bowed String 由弓噪、锯齿激励、琴体带通和空间送出组成。
2. **起音、持续、释放分开**：起始有锤击/弓噪瞬态；持续有独立模态衰减与慢漂移；释放有独立阻尼时间。
3. **频谱随时间演化**：高次模态衰减更快；力度改变模态倾斜；失谐产生拍频；持续音有低深度漂移。
4. **相似而不相同**：同音重复通过固定种子、锤击位置、弦组失谐和相位差异产生相关变化，不是逐音白噪。
5. **参数联动有界**：力度、亮度、噪声、起音、释放都经过 clamp；非法输入被安全值替换。
6. **方法选择有理由**：毡音钢琴用混合模态 + 噪声激励；弓弦用锯齿 + 弓噪 + 琴体滤波；玻璃用非谐和模态；低音用正弦 + 锯齿 + 饱和；鼓用正弦瞬态 + 滤波噪声。
7. **实时安全**：合成器在 `prepare()` 中预分配，`noteOn()` 和 `render()` 不分配内存；不使用互斥锁；NaN/Inf 被替换。
8. **复现**：每个音符的随机相位/失谐由 note/track/pitch 派生；工程 seed 固定时结果可复现。
9. **关闭混响仍可信**：Felt Piano 与 Bowed String 的主体在干声路径中；测试在没有 master reverb 的 `SynthEngine` 层验证非静音。
10. **不虚构采样库/模型接口**：全部声音为程序化合成，没有声称使用采样或神经网络音色。

### 2.2 未做到或只能部分做到

- 没有真实毡音钢琴采样，因此无法声称与真实乐器在听感上无差别；它是**物理启发式合成**。
- 没有建模踏板共鸣、琴弦耦合、音板有限元等完整物理细节；这些属于 P1/P2。
- 没有进行实际盲听；所有音质结论只到客观测量与设计审查级别。
- 鼓组是合成鼓，不是采样鼓；在高密度电子风格中可用，但不声称录音级真实。

## 4. 关键假设

1. 默认目标平台是 Windows x64 + VST3/Standalone；macOS AU 需要 macOS + Xcode 才能实际构建，当前 Windows 环境不能诚实验证 AU。
2. 默认采用 12-TET、西方功能和声作为第一套规则包；这不是“通用音乐真理”，文化/风格可替换。
3. 宿主提供 PPQ 位置与 BPM；如果宿主不提供，插件回退到内部试听时钟。
4. 单插件不能读取 DAW 所有轨道；本工程不做跨轨混音分析，也不假装拥有该能力。
5. 云模型默认关闭，P0 不依赖网络；当前没有接入任何云模型。
6. 产品以 MIDI/工程数据为核心，音频渲染是验证和试听手段，不是唯一交付物。

## 5. 最大技术风险

| 风险 | 影响 | 当前缓解 |
|---|---|---|
| 生成结果“像规则练习”而非音乐 | 艺术目标失败 | 动机追踪、段落对比、三风格规则包、人工评价表；仍需真实听音 |
| 单插件实时合成 CPU 高 | 爆音/丢帧 | 预分配、96 声部上限、离线渲染基准；未在真实 DAW 做长期压力测试 |
| JUCE/VST3 许可 | 分发合规 | 工程选择 AGPL-3.0；商业分发需 JUCE 商业许可，已在许可证文档标注 |
| AU/CLAP 无法在 Windows 验证 | 跨平台承诺不完整 | 明确标记为未验证；CLAP 扩展可选、子模块未初始化 |
| 宿主兼容性 | 插件在特定 DAW 不工作 | 提供 Standalone 与 VST3 构建；仍需实际 DAW 验证 |
| 音色“自然感”不足 | 艺术目标失败 | 模态/弓噪/联动/漂移；仍不能声称听感已验证 |
| 局部重生成语义复杂 | 用户锁定被破坏 | 显式 lock mask + range merge + 测试；UI 仍需更多边界测试 |
| `tools.zip` 缺失 | 无法复用已有原型 | 不依赖它从零实现；审计项保持未完成 |

## 6. 默认技术选型

- C++20，CMake 3.22+，MSVC 2022（Windows）。
- 核心：无第三方依赖的静态库 `ec_core`。
- I/O：自有 SMF/WAV 读写（无第三方 MIDI 库）。
- DSP：自有模态/弓弦/滤波/非线性/混响/动态代码。
- 插件：JUCE 8.0.6（AGPLv3 或商业许可），VST3 + Standalone；AU 条件构建。
- UI：JUCE 自绘组件，不依赖 WebView。
- 测试：轻量测试框架 + CTest；不把 Python 原型当作实时核心。
- Python：未用于产品核心；如后续需要分析脚本，仅作为离线研究工具。
